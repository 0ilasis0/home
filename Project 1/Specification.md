一、 專案題目與目標題目名稱：Digital Circuit Design and Analysis 115-1 Project I - Triangle Rendering Engine (三角形座標轉譯系統)。   系統目標：接收 testbench 提供的三角形三個頂點座標 (x1, y1)、(x2, y2) 與 (x3, y3) 後，系統需轉譯並依序輸出涵蓋於該三角形平面內的所有座標點。   輸出順序：必須嚴格遵守「先由左而右，再由下而上」的順序來輸出結果。
二、 輸入/輸出介面規格所有的輸入及輸出資料均為 3 個位元，且皆以 10 進制表示：   clk (Input, 1-bit)：系統時脈信號，電路需同步於時脈正緣。   reset (Input, 1-bit)：高位準非同步之系統重置信號。   nt (Input, 1-bit)：三角形座標的輸入標記，高位準時表示有 3 組頂點座標輸入（僅在 busy 信號為低位準時有效）。   xi, yi (Input, 3-bit)：分別為三角形頂點座標的 X 軸與 Y 軸輸入值。   busy (Output, 1-bit)：高位準時表示系統正在運作，此時需防止下一個新的三角形頂點輸入。   po (Output, 1-bit)：有效資料輸出指示信號，當為高位準時，表示 xo 及 yo 輸出的資料為有效的座標。   xo, yo (Output, 3-bit)：分別為三角平面內涵蓋之座標點的 X 軸與 Y 軸輸出結果。
三、 核心設計邏輯與數學限制圖形特徵：輸入的三個頂點具有 x1 = x3 以及 y1 < y2 < y3 的關係，數值均為正整數，代表此三角形的其中一邊必定是垂直線。   平面內座標鑑別法：若一條線段經過 (x1, y1) 與 (x2, y2) 兩點，可利用下列關係式來判斷座標點的位置：   位於該線段上的座標點滿足：(x - x1) / (y - y1) - (x2 - x1) / (y2 - y1) = 0。   位於該線段右邊的座標點滿足：(x - x1) / (y - y1) - (x2 - x1) / (y2 - y1) > 0。   位於該線段左邊的座標點滿足：(x - x1) / (y - y1) - (x2 - x1) / (y2 - y1) < 0。
四、 時序規格與評分標準時序參數：時脈週期 (T_cycle) 由使用者自行定義，Setup time 與 Hold time 均要求大於 0.5ns。   基本分數：完成 RTL simulation 與 Gate-level simulation，且結果正確無 setup/hold time 違規，可獲得基本分 80 分。   效能評估 (Performance Metric)：計算方式為 Time Complexity 乘上 Area Complexity，數值越低代表電路效能越好。   Time Complexity 從 ncverilog 產生的 ncverilog.log 取得；Area Complexity 則從 Design Compiler 產生的 Report 得知。
五、 晶片開發與繳交要求頂層模組宣告：必須使用 triangle.v，且介面須精準宣告為 module triangle (clk, reset, nt, xi, yi, busy, po, xo, yo);。   RTL 階段提交：設計報告 (.doc) 以及 Synthesizable RTL code (.v)。   Gate-Level 階段提交：由 Synopsys Design Compiler 產生的 Gate-level netlist (_syn.v)、Pre-layout SDF 檔 (_syn.sdf)，以及 Ncverilog 產生的波形檔 (*_syn.vcd) 與日誌檔 (ncverilog.log)。
六、 細部時序與邊界條件釐清nt 的輸入時序：nt 脈波寬度僅維持一個時脈週期的高位準（Tnt=Tcycle ）。系統將在 nt 轉為高位準的當下與接下來的兩個週期，連續三個 cycle 依序讀入 (x1, y1)、(x2, y2) 與 (x3, y3)。busy 拉高的時機：busy 信號必須在「(x3,y3) 頂點座標輸入前」由低位準提昇至高位準，以防止下一個三角形的座標提早輸入系統。當所有運算與輸出結束後，busy 才會降回低位準。邊界與頂點的處理：系統輸出的座標必須完全包含三角形的三個頂點本身，以及落在邊界線段上的所有座標點。此邏輯對應於設計提示中座標關係式結果「=0」的判斷條件。po 的輸出時序：當 po 為高位準時，代表該時脈週期所輸出的 xo 與 yo 為有效座標。每輸出一組有效座標即佔用一個時脈週期，系統必須嚴格遵守「先由左而右，再由下而上」的規則依序拉高 po 並給出結果。
七、 邊角案例與精確時序定義 (Edge Cases & Exact Timing)② busy 拉高時機的精確 Cycle：規格書明訂「待(x3,y3)頂點座標輸入前，busy 信號必須由低位準提昇至高位準」。配合圖三的時序圖，硬體行為應嚴格定義如下：   Cycle N：nt = 1，讀取 (x1, y1)。   Cycle N+1：nt = 0，讀取 (x2, y2)。在這個 Cycle 的正緣觸發後，電路需將 busy 準備拉高。   Cycle N+2：nt = 0，讀取 (x3, y3)。此時 busy 已經是 1，成功擋住後續無效的輸入。   ③ busy 下降時機：根據圖三波形圖最後段的呈現，當最後一組座標輸出時（po = 1），busy 仍維持在高位準。直到最後一個 po 脈波結束並降回 0 之後，busy 才會在隨後的時脈週期降為 0。這意味著 FSM 在輸出完最後一個點後，至少需要經過一個過渡 cycle 才會解除 busy 狀態。   ④ 連續輸入 (Back-to-back) 行為：規格書表一明確指示：「只有當 busy 信號為低位準時，nt信號才能為高位準」。這代表 Testbench 會嚴格遵守交握協定（Handshake），絕對不會在 busy = 1 的期間拉高 nt 塞入新資料。系統只要負責在算完所有座標後將 busy 歸零，就能安全等待下一個三角形。   ⑤ 座標範圍 (0~7 vs 正整數) 的矛盾：這是一個非常關鍵的觀察！規格書 2.3 節的文字確實寫著「均為正整數」。但是，在附錄 A 的測試樣本一中，頂點包含了 (1,0)（也就是 y1=0）；而測試樣本二中，頂點包含了 (0,3)（也就是 x2=0）。既然官方提供的 Testbench 確實驗證了數值 0，加上信號寬度定義為 3-bit，我們的硬體設計必須支援 0 ~ 7 的完整無號數範圍。把「正整數」視為文件敘述的筆誤，以測試資料為準。
